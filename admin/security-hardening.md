本指南面向将 KodBox 暴露于公网或承载敏感企业数据的系统管理员，集中梳理 v1.70.03+ 的二次验证（2FA）、防爆破限流、设备与权限审计以及底层 PHP 安全补丁升级的标准加固流程。

## 1. 启用二次验证（2FA）与防爆破限流

二次验证（Two-Factor Authentication）要求用户在输入账号密码之外，再提供一次性动态验证码（如 TOTP 身份验证器、短信或邮件验证码），可有效阻断撞库与弱密码导致的账号沦陷。

- **管理员全局策略**：进入 **后台管理 → 安全管控 / 基础设置**，为管理员账号及高敏部门强制开启二次验证，并开启登录失败次数限制与验证码保护。
- **v1.70.03 防爆破限流强化**：新版对二次验证校验接口强化了**限流防爆破机制**，短时间内连续输错动态码会触发强制冷却锁定，阻断暴力穷举 6 位验证码。
- **第三方登录联动注意点**：
  - 当系统同时对接了企业微信、钉钉、飞书、AD/LDAP 或 OAuth2 单点登录时，请提前确认：**第三方免密扫码登录是否受 2FA 策略约束**，以及员工在「账号中心」绑定 2FA 密钥后，若更换手机应由管理员在后台协助解绑重置，避免被锁在门外。
  - 若第三方认证本身已强制启用企业级 MFA（如企业微信/钉钉自带的设备验证），请在评估体验后决定是否对内部成员免除重复二次校验。

## 2. 强制 HTTPS、设备管理与动态水印

1. **全站强制 HTTPS**：任何公网站点均应通过反向代理强制跳转 HTTPS，并配置完整证书链（详见 [HTTPS 反向代理与非标准端口配置](/setup/reverse-proxy/)）。
2. **登录管控与真实 IP 还原**：在 **后台管理 → 登录管控** 中按用户/部门限制允许登录的设备类型（Web / PC / App）与允许/禁止的 IP 段。若站点前方存在 Nginx 或 CDN，**必须正确配置真实 IP 透传**，否则所有登录来源都会被识别为反代内网 IP，导致 IP 管控形同虚设。
3. **动态文档水印**：针对财务、研发、法务等高敏部门开启文字/图片动态水印，并嵌入「用户账号 + 昵称 + 当前时间」变量，震慑拍照与截屏泄密（详细步骤见 [6.1 安全审计与文档水印](/admin/6/)）。

## 3. 部门级权限审计与防越权加固

- **及时升级获取越权校验修复**：KodBox v1.70.03 强化了后端接口的**部门级越权校验**与 `aiRag` 语义检索的文件权限隔离，防止构造异常参数越权访问非所属部门资源。
- **遵循最小权限原则**：
  - 日常使用勿分发超级管理员账号，普通运维按需拆分系统角色权限。
  - 外挂本地目录/对象存储默认仅管理员可见，严禁将系统敏感目录（如 `/`、`/etc`、`/var/www/html/config`）直接作为本地存储挂载进网盘。
  - 定期在 **后台管理 → 分享管理** 中巡检长期有效的无密码公开外链，及时关闭过期分享。

## 4. 及时升级官方镜像与底层 PHP 安全补丁

除了升级 KodBox 自身代码，底层运行环境（PHP、Nginx、MariaDB、Redis）的漏洞同样构成高危风险：

- **Docker 部署用户**：定期拉取最新官方镜像，例如 `kodcloud/kodbox:1.70.03` 已内置**修复版 PHP 8.5.12**。标准无损升级流程见 [版本升级指南](/operations/upgrade/)。
- **传统 LNMP / 宝塔部署用户**：请对照 [PHP 支持分支建议](/setup/environment/#php-branches)，将已停止官方安全维护的 PHP 7.x / 8.0 / 8.1 尽快迁移至仍在维护周期内的 **PHP 8.3 / 8.4 / 8.5**，并禁止 Nginx 直接访问 `/config` 与 `/data` 目录（Nginx 安全片段见 [Nginx 配置优化](/setup/nginx/)）。

## 5. 验证安全加固是否生效（Success Check）

完成加固后，请逐项核验：

1. **验证 2FA 与限流**：使用测试账号开启 2FA，退出重新登录确认必须校验动态码；故意连续输入错误验证码，确认触发限流保护。
2. **验证敏感目录不可直接访问**：在浏览器尝试访问 `https://你的域名/config/setting_user.php` 与 `https://你的域名/data/`，确认均返回 `403` 或 `404` 而非源码或目录列表。
3. **验证日志与真实 IP**：检查 **后台管理 → 登录日志 / 操作日志**，确认客户端公网/内网真实 IP 记录准确、非代理网关 IP。
4. **核对运行版本**：在 **后台管理 → 概览**（或 `docker exec kodbox-app-1 php -v`）确认 KodBox 与 PHP 均处于受支持的安全版本。
