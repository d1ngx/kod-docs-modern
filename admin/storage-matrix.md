KodBox 支持在同一个网盘实例内同时挂载多种异构存储，并像操作本地磁盘分区一样跨存储迁移文件。在添加新存储前，请对照下表评估接入方式、CORS 跨域要求、缩略图支持度与限速边界。

## 一、全存储后端能力对比总表

| 存储后端 | 接入协议 | 浏览器直传 & CORS 要求 | 缩略图 / 封面支持 | 传输限速边界 | 典型适用场景 |
| --- | --- | --- | --- | --- | --- |
| **本地磁盘（托管默认）** | 本地文件系统 | 无需 CORS（走服务器中转） | 支持本地缩略图生成 | 原生服务端上传受底层限制，不支持精细限速 | 主力默认存储、私有服务器/NAS |
| **本地目录（直接挂载）** | 本地/NFS/SMB 挂载 | 无需 CORS | 完整支持 | 同上 | 纳管 NAS 既有共享目录（不含去重秒传） |
| **阿里云 OSS** | 厂商驱动 / S3 兼容 | **直传必配 CORS** | 支持（配合 OSS 处理或服务器拉取） | **直传模式支持部分厂商侧限速** | 阿里云 ECS 内网回源 + 公网直传分发 |
| **腾讯云 COS** | 厂商驱动 / S3 兼容 | **直传必配 CORS** | 支持 | 同上 | 腾讯云 CVM 混合架构与企业云盘 |
| **七牛云 Kodo** | 厂商驱动 / S3 兼容 | **直传必配 CORS** | 支持 | 依七牛 Bucket / CDN 策略 | 静态资源分发与媒体库 |
| **百度云 BOS** | 厂商驱动 / S3 兼容 | **直传必配 CORS** | 支持 | 依云厂商策略 | 百度智能云私有化部署 |
| **MinIO（自建）** | 通用 S3 协议（Path-Style） | **直传必配 CORS** | 支持 | 受服务端/反代带宽限制 | 内网私有对象存储集群、多节点共享后端 |
| **Cloudflare R2** | 通用 S3 协议 | **直传必配 CORS**（且需独立 R2 API Token） | 支持 | 零出口流量费，适合公开分发 | 个人/团队低成本跨地域对象存储 |
| **通用 S3（如移动云/天翼云/AWS）** | 标准 S3 v4 签名 | **直传必配 CORS** | 支持 | 依厂商支持情况 | 各类兼容 AWS S3 API 的对象存储 |
| **外部 FTP / SFTP** | FTP 协议 | 无需 CORS（服务器中转） | 受限（大视频缩略图耗流量且可能失败） | 仅受链路带宽限制 | 传统企业旧 FTP 服务器平滑接入 |
| **外部 WebDAV** | WebDAV 协议 | 无需 CORS（服务器中转） | **受限**（视频缩略图受限，依赖远端性能） | 受上游网盘限速（如 123 云盘易触发速率限制与分片合并失败） | 临时挂载外部 NAS 或辅助网盘 |

> **关于上传限速与外挂可见性的两项重要边界**
>
> 1. **原生上传限速边界**：受 PHP/Web 服务器原生上传机制限制，KodBox 本地服务端中转上传通常无法做到精准单连接限速；仅在对接部分支持客户端直传的对象存储时，可通过对象存储策略实现精细限速。
> 2. **外挂存储默认仅系统管理员可见**：在 `后台管理 → 存储管理` 新增的任何非默认存储，默认仅系统管理员可见。如需让普通员工使用，请通过绑定部门空间或创建「协作分享」分发（详见 [组织架构与细粒度权限模型](/concepts/permissions-model/)）。

## 二、中转模式 vs 直传模式与内外网分流

接入对象存储时，必须根据服务器网络位置合理选择流量路径：

- **客户端直传（推荐公网场景）**：浏览器直接把文件上传到 OSS/COS/R2，大幅节省 KodBox 服务器公网带宽。前提是**必须在 Bucket 上正确配置 CORS 跨域规则**，且前端配置的 Endpoint 为公网 HTTPS 域名。
- **服务器内网中转上传 + 网页公网下载**：当 KodBox 与对象存储位于同一云厂商同地域（如阿里云 ECS + 同区 OSS）时，若希望服务端后台任务（如缩略图、全文索引、定时备份）走免费高速内网，而用户浏览器下载走公网/CDN 加速域名，请在存储配置中区分**服务端 Endpoint（内网）**与**访问域名（公网 HTTPS / 自定义域名）**。详细写法见 [对象存储实战指南](/admin/storage-s3/#三服务器内网中转与公网下载分流注意事项)。

## 三、删除文件后为何对象存储未立即释放空间？

在托管模式下，KodBox 删除文件会先经过「个人回收站 → 系统回收站 → 历史版本清理 → 去重引用计数归零」四道保护，并非系统故障。完整原理解析请见：[虚拟文件系统与存储托管原理](/concepts/storage-architecture/#s3-delete-lifecycle)。
